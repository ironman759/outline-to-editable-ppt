# 逐页施工稿与资产对应

任务首页记录用途、受众、结论、时长、部分顺序、当前源文件、保留项、视觉参考、输出路径与已确认事项。未知项写待确认，不填成事实。新项目按工作区规则建立目录，同一项目沿用原入口。

每页用稳定 ID（如 `mechanism-transfer`），不以会变化的页码作为身份：

| 字段 | 应记录内容 |
|---|---|
| ID、部分、页型、显示页码 | 封面、目录、章节、机制、证据、对比、总结等 |
| 本页问题与核心结论 | 叙事作用 |
| 准确上屏文案 | 标题、正文、图注、数字、单位、强调词 |
| 证据及边界 | 源文件定位，已完成/设想/待补；不跨批次拼数据 |
| 排版 | 区域位置、比例、对齐、间距、裁剪和留白，英寸或百分比 |
| 字体 | 中英文，标题/正文/图注/强调/页码字号、字重、颜色 |
| 资产及生图 | 资产 ID/路径、生图任务 ID、参考图片、BioArt 对象及结构约束 |
| 原生对象计划 | 文字/数字/表格/箭头/图形；哪些复杂插图保留独立图片 |
| 讲稿、预计秒数、衔接 | 完整讲稿、前后页过渡；时间为预算而非实测 |
| 审阅和版本 | 大纲确认、视觉确认、重建审阅、必要纠错 |

资产清单记录 ID、路径、来源/许可信息（已有时）、用途、使用页与状态。生图任务记录 ID、目标页、参考资产、准确文案、风格和机制约束、输出路径及审阅版本。现有资产优先作参考；初稿只生成概念仪器，不主动找真实仪器照片。机构 logo 使用现成用户资产。

## 单一讲稿 manifest

JSON 中 `slides` 顺序等于最终 PPT 顺序。额外资产/视觉映射字段可保留，脚本只解释以下字段：

```json
{
  "title": "汇报名称", "font": "Microsoft YaHei",
  "slides": [{"id": "mechanism-transfer", "section": "系统实现", "title": "从操作动作到自动化流程", "seconds": 60,
    "script": "本页说明液滴操作如何组织为流程。图中设备为概念插图。"}]
}
```

重排时按稳定 ID 修改 manifest，再重排原生页并同步。重建时将稳定 ID 存在 slide XML 的 `p:cSld/@name`，值为 `page-id:<id>`；Python 写法：`slide._element.cSld.set("name", "page-id:" + page["id"])`。标签随页面一起移动。已有 PPT 无标签时先人工核对施工稿和对象映射再补，不能只按当前位置盲写 ID。

同步工具核对页数、稳定 ID 和独立原生标题对象的全文，避免重复标题或标题出现在正文导致错挂。所有页包括封面/图片页应有准确原生标题。复制同页时给新页新 ID；Office 或合并器若移除 ID，先复核再补，不关闭校验。
