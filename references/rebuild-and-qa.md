# 忠实重建与验收

逐页查看整页视觉稿，为每个对象记录类型、bbox、文案/字体/字号/颜色、层级、裁剪和引用资产。复杂设备/生物插图可提取为独立图片，保留比例；文字、数字、箭头、简单图形和可重建表格从准确施工稿做原生对象。对照视觉稿与原生渲染检查构图、位置、比例、留白和强调关系；并排图或叠加图辅助定位。修正科学或文字错误需记录，大幅改版需用户确认。

采用保持关系/媒体/备注一致的构建与合并方法，不直接拼接 ZIP 中的 slide XML。`python-pptx` 或已有验证工具均可。PptxGenJS 备注及黑红混排历史故障：每个 `a:p` 最多一个 `a:pPr`，强调用 run-level `a:rPr`；`presentation.xml` 的 `notesMasterIdLst` 在 `sldIdLst` 前。这只是已发现故障，不是完整根因清单，修两项不能替代真实应用验收。

## 讲稿同步

源 PPT 先保存关闭或另存工作副本。同步会完整覆盖每页备注正文：先核对旧备注，将必须保留的讲稿、提醒或引用迁入 manifest。脚本给已重建的原生 PPT 同步备注及 Word，不识别视觉稿、不改变页序/布局。页数、稳定 ID 及独立原生标题必须与 manifest 对应，讲稿回读一致才通过。

```bash
python scripts/sync_scripts.py working/native.pptx working/slides.json \
  --pptx exports/汇报.pptx --docx exports/逐页讲稿.docx
python scripts/check_pptx.py exports/汇报.pptx \
  --manifest working/slides.json --docx exports/逐页讲稿.docx
```

用桌面依赖工具返回的 Python（现有 python-pptx、python-docx）。复杂已有模板先对副本做代表页 roundtrip 检查，不适合脚本时可用 Office 工具，仍保持单一讲稿源与回读。每次改序、改标题/讲稿都重新同步，不单独发挥另一份。两个输出分别落盘，不承诺共同原子替换；若写入报错，检查两份版本并重新从源同步，不能交付半更新的组合。

## 多层验收

1. 内容/证据：逐页与施工稿对应，数字/单位/机制和已完成/设想边界正确，页序及内容不遗漏。
2. 编辑性：原生文字/数字/简单图形/表格、独立插图，不能全屏图片冒充。脚本只检查非空文字/表格，不能证明主体可编辑；按对象映射核对所有必需原生对象，并实际抽查编辑。仅标题/页码原生、主体为截图仍不合格。
3. 视觉：全部渲染检查裁切、重影、原图标签残留、重复文字、行首标点、扭曲、假数据。复杂页独立 reviewer 审阅，修后重看相关页。
4. 结构/同步：ZIP、XML、关系、媒体、页界、无动画/自动播放；封面/目录/章节/正文/页码闭合；notes 和 Word 与 manifest 对应。脚本对组内文字递归核查，页界仅检查顶层/组框，组内缩放或旋转后的裁切须渲染核查。检查脚本不代替内容和视觉审阅。
5. 应用：真实 PowerPoint 打开最终文件，无“发现内容有问题/修复”提示，抽查页面和备注；新构建路径另存测试副本再重开，复核对象/讲稿仍在。不能点击修复后称原文件通过。尊重用户的桌面操作限制：用户不允许操控电脑时不调用 Computer Use；可由用户自行打开反馈，在获得真实结果前标记“应用兼容性待验证”，不重复要求操作权限。
6. 交付：PPTX＋DOCX；PDF/PNG 为内部 QA，用户要求时才交付 PDF。记录哈希、实际结果/限制并更新唯一入口。初稿后再反馈优化。

原型优先覆盖备注、多段文字、黑红富文本、图形、图片及页码，通过后才规模制作。修复提示出现则留失败副本和证据，定位构建/合并；相同方案三轮无进展后换可靠路径。无法真实验证须标明兼容性待验证，不能删除备注绕过要求。
